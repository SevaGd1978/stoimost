# 🕵️ Tender Spy — мониторинг тендеров по номенклатуре

Веб-приложение, которое следит за закупками в ЕИС (zakupki.gov.ru, 44-ФЗ / 223-ФЗ / 615-ПП)
и на 8 открытых электронных площадках по списку наблюдения (только закупки, без продажи имущества):

- **номенклатура** — ключевые слова (с учётом словоформ) и/или коды ОКПД2.

Новые закупки подсвечиваются в ленте, приходят уведомлением в браузер и, при желании, в Telegram.

## Запуск

```bash
cd tender-spy
npm install
npm start            # http://localhost:3000 — реальные данные ЕИС
npm run demo         # демо-режим: карточки генерируются локально, без сети
```

С переменными из файла: `cp .env.example .env`, затем `npm run start:env`.

Требуется Node.js ≥ 18 (для `start:env` — ≥ 20.6).

### Развертывание в облаке Amvera (amvera.ru)

В корне репозитория подготовлены конфигурационные файлы `amvera.yml` и `Dockerfile`:
- Среда: Docker-образ на Node.js 20 (Debian bookworm) с LibreOffice, шрифтами и `unar` — они нужны кнопке «Извлечь документы».
- Порт: 3000 (по умолчанию).
- Постоянное хранилище: `/data` (база автоматически монтируется по пути `/data/db.json` при наличии переменной `AMVERA` или `TENDER_SPY_DATA=/data/db.json`).
- Для развертывания:
  1. Создайте приложение в Amvera.
  2. Добавьте remote: `git remote add amvera https://git.amvera.ru/<username>/<app-name>`.
  3. Отправьте ветку: `git push amvera HEAD:master`.
  4. В панели Amvera задайте необходимые переменные (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TENDER_SPY_POLL_MIN`).
  5. **Вход.** Сайт закрыт учётками. Если пользователей ещё нет, первая открытая страница просит создать администратора (логин латиницей, пароль от 8 символов). Либо задайте `TENDER_SPY_ADMIN_LOGIN` и `TENDER_SPY_ADMIN_PASSWORD` (старые имена `TENDER_SPY_USER` и `TENDER_SPY_PASSWORD` тоже подходят) — администратор создастся при запуске, только пока в базе никого нет. `/health` остаётся открытым для мониторинга.

## Как пользоваться

Войти можно как **администратор** или **сотрудник**. Администратор управляет номенклатурой, настройками, опросом, архивом и учётными записями (вкладка «Настройки»). Сотрудник смотрит ленту, аналитику и журнал, добавляет закупки в избранное, пишет заметки и извлекает документы. Сменить свой пароль может каждый, в «Настройках».

1. **Наблюдение** → добавьте позиции номенклатуры вручную или загрузите файл (CSV, TXT, JSON, Excel .xlsx) кнопкой **Импорт файла**. Колонки: «Ключевые слова» и «ОКПД2». Это доступно администратору.
   У позиции можно задать **уточняющие слова** (кнопка ✏️): закупка берётся, только если в её названии есть хотя бы одно из них. Например, для «ППУ» — `труб, изоляц, скорлуп, отвод, фасон, компенсатор`: так отсеиваются «втулка ППУ» в буровом инструменте и совпадения только в документах.
2. Нажмите **Опросить сейчас** или дождитесь автоопроса (интервал — в настройках). В **Настройках** можно задать цену закупки (НМЦК) «от» и «до» — она уходит прямо в запрос к ЕИС и к площадкам, где есть такой фильтр. Там же включаются и выключаются отдельные площадки.
3. **Лента** → фильтры по номенклатуре, закону, площадке, типу (извещение/контракт), диапазону цены (от и до) и сроку подачи. Второй ряд:
   - **по текущим настройкам** (включено по умолчанию) — скрывает закупки по удалённым позициям номенклатуры, по выключенным законам, с ценой вне диапазона, с минус-словами и без уточняющих слов; избранные видны всегда;
   - **регион** и **осталось дней** — регион и срок подачи для ЕИС дочитываются из карточки извещения в фоне после опроса (до 40 карточек за опрос, с паузой). Закупки, у которых срок ещё не известен, фильтр «осталось дней» не скрывает;
   - **предмет** (поставка / работы и услуги), **тип заказчика** (теплоснабжение и энергетика, муниципальные и ЖКХ, промышленные, бюджетные), **способ** (аукцион, котировки, запрос предложений, конкурс, иной), **СМП** (скрыть или показать только закупки для субъектов малого и среднего предпринимательства), **размещено** за сутки / 3 дня / неделю / месяц.
   **Минус-слова** задаются в настройках: закупки с ними не попадают в ленту при опросе и скрываются из уже собранной ленты.
   На каждой карточке видно, *почему* она попала в выборку (чипы «ключевая фраза» / «ОКПД2»).
   Полупрозрачный чип — совпадение выдано ЕИС, но в тексте карточки не подтверждено.
   Бейджи «ЕИС», «Росэлторг», «Фабрикант»… — где найдена закупка, каждый ведёт на карточку этой площадки.
4. Действия по карточке: «☆ В избранное», «📋 В воронку», ✓ прочитано, 🗄️ архив. Смена этапа закупки снова делает карточку «новой».
5. Вкладка **📋 Воронка** — встроенная CRM участия. Закупка из ленты или избранного становится карточкой сделки: отобрано → изучаем → готовим заявку → заявка подана → победа или отказ. У карточки есть ответственный сотрудник, сумма предложения, следующий шаг и комментарии. Карточку можно перетащить в другой столбец. Открытая сделка не удаляется при очистке ленты; взятая в воронку закупка попадает в избранное. Убрать из воронки может администратор.
5. Вкладка **⭐ Избранное** — закупки, отложенные для дальнейшего рассмотрения. На карточке есть кнопка **Юридическая проверка**: по ИНН заказчика открывается бесплатная карточка на Saby (надёжность, выручка, долги, суды, исполнительные производства). Если ИНН ещё не дочитан из карточки ЕИС, открывается поиск по названию на Чекко. Рядом кнопка **Объём закупок**: по ИНН заказчика читается бесплатная RSS-выгрузка реестра контрактов ЕИС (не больше 50 последних записей) и закупки этого заказчика, уже лежащие в Tender Spy. Одинаковые номера не суммируются дважды. График — сумма контрактов по году заключения; если контрактов нет, показываются начальные цены извещений. Ссылка «Открыть реестр ЕИС» ведёт на полный бесплатный поиск. В демо-режиме запрос к ЕИС не уходит. Кнопка не включает поиск по ИНН в периодический опрос. Сюда попадает всё, что отмечено «☆ В избранное», в том числе архивные и уже закрытые закупки. У каждой карточки есть поле заметки (сохраняется, когда курсор уходит из поля; заметка видна и в ленте, по ней работает поиск). Есть сортировка по дате добавления, сроку подачи и цене, отбор «только открытые» и выгрузка в CSV с колонкой «Заметка». Избранное не удаляется при очистке и устаревании карточек. Открытые избранные с окончанием подачи в ближайшие 3 дня и сутки показываются полосой сверху вкладки; в эти же моменты приходит уведомление браузера и, если Telegram включён, одно сообщение.
6. Кнопка **📄 Извлечь документы** на карточке во вкладке «Избранное» скачивает документацию закупки из ЕИС и собирает её в один PDF для просмотра:
   - файлы берутся с вкладки «Документы» карточки ЕИС (44-ФЗ и 223-ФЗ; файлы недействующих редакций пропускаются), первой идёт печатная форма извещения, если ЕИС её отдаёт;
   - архивы ZIP/RAR/7z распаковываются (и вложенные — ещё на один уровень), Word/Excel/RTF/HTML переводятся в PDF через LibreOffice, PDF и картинки добавляются как есть, файлы подписи пропускаются;
   - в начале PDF — титульный лист с содержанием и номерами страниц, в PDF есть закладки по каждому документу;
   - большие таблицы обрезаются до 60 страниц, прочие документы — до 300, весь PDF — до 1500 страниц; об обрезке сказано в содержании, оригиналы можно скачать по ссылкам в «Составе»;
   - ход работы виден на карточке, результат хранится рядом с базой (`documents/`) и переживает перезапуск; закупки обрабатываются по одной (остальные ждут в очереди), неудачное «Обновить» оставляет прошлый PDF;
   - документы закупок, убранных из избранного больше 30 дней назад или удалённых из базы, стираются автоматически после опроса;
   - если закупка площадки опубликована и в ЕИС (заказчики вроде «Т Плюс» пишут номер площадки в скобках в названии), документы берутся из ЕИС; у закупок только с площадки документация выдаётся после входа в личный кабинет площадки — в таком случае кнопка сообщает об этом.
5. **CSV** — выгрузка текущей выборки (разделитель `;`, кодировка UTF-8 с BOM — открывается в Excel).
6. **Журнал опросов** — какие запросы ушли, сколько найдено, ошибки ЕИС.

## Откуда данные

ЕИС не предоставляет публичного REST API; приложение читает **RSS расширенного поиска**:

| Что ищем | Запрос к ЕИС |
|---|---|
| Извещения по номенклатуре | `/epz/order/extendedsearch/rss.html?searchString=<слова>` и/или `okpd2IdsCodes=<код>`; при заданной в настройках цене — `priceFromGeneral` / `priceToGeneral` |

Точные URL можно увидеть в разделе «Наблюдение → Какие запросы уйдут в ЕИС». Имена параметров
вынесены в `src/sources/zakupki.js` (`QUERY_TEMPLATES`) — если ЕИС переименует поля формы, правится одно место.

Важные ограничения самого ЕИС:

- поиск идёт только по тексту извещения и коду ОКПД2, без отбора по ИНН заказчика или поставщика;
- с 4 июля 2026 ЕИС предъявляет сертификат Минцифры (Russian Trusted Root CA). Он не входит в набор корней Node.js, поэтому приложение само добавляет официальные PEM из `certs/` и проверяет TLS как обычно — проверка не отключается;
- ЕИС ограничивает частоту запросов и доступ с зарубежных IP — используйте паузу `TENDER_SPY_REQUEST_DELAY_MS`
  ≥ 1000 мс и запускайте сервер из России (или через российский прокси);
- в RSS попадают первые 50 записей на запрос по дате обновления — для широких ключевых слов уточняйте фразу или ОКПД2;
- ЕИС годами показывает брошенные извещения на этапе «Подача заявок». Извещение без срока подачи, опубликованное больше 90 дней назад, считается закрытым: этап «… (запись устарела)».

### Электронные площадки

Помимо ЕИС каждое ключевое слово номенклатуры ищется в открытых реестрах площадок (без авторизации).
Позиции только с кодом ОКПД2 на площадки не уходят — площадки ищут по тексту.

| Площадка | Что там | Фильтры в запросе |
|---|---|---|
| Росэлторг (roseltorg.ru) | 44-ФЗ, 223-ФЗ, коммерческие | приём заявок, цена |
| НЭП / ЭТП ЕТС (etp-ets.ru) | 44-ФЗ | приём заявок, цена |
| Фабрикант (fabrikant.ru) | 44-ФЗ, 223-ФЗ, коммерческие | — |
| ТЭК-Торг (tektorg.ru) | 223-ФЗ, закупки ТЭК (разделы продаж отсеиваются) | приём заявок, цена |
| B2B-Center (b2b-center.ru) | коммерческие и 223-ФЗ | только актуальные |
| АГЗ РТ (etp.zakazrf.ru) | 44-ФЗ, 223-ФЗ | — |
| ЭТП РФ (etprf.ru) | коммерческие | — |
| Автодор-ТП (etp-avtodor.ru) | закупки дорожной отрасли | цена |

Как это работает:

- площадки опрашиваются параллельно, запросы к одной площадке — по очереди с паузой 1 с;
- в ленту попадают только позиции, в названии которых есть все слова ключевой фразы (с учётом словоформ);
- там, где у площадки нет фильтра, «только открытые» определяется по сроку подачи заявок, цена — по цене в карточке; закупки без цены не отбрасываются;
- извещение с номером ЕИС (11 или 19 цифр) сливается с карточкой ЕИС: этап и основная ссылка берутся из ЕИС, площадка добавляет свою ссылку;
- продажа имущества в ленту не попадает: отсеиваются разделы продаж ТЭК-Торга и Фабриканта, секции имущественных торгов Росэлторга и процедуры, где способ или предмет говорят о продаже («Продажа…», «реализует…», в том числе с латинскими буквами вместо русских). Уже сохранённые карточки продаж удаляются при запуске, кроме избранных;
- если площадка дважды подряд не отвечает, остальные запросы к ней в этом опросе пропускаются, ошибка видна в журнале.

Разбор каждой площадки — отдельный модуль в `src/sources/platforms/`; тесты сверяют его с сохранённой реальной выдачей
(`test/fixtures/platforms/`). Сервер etprf.ru не присылает промежуточный сертификат, поэтому он лежит в `certs/`.

Не подключены: Сбербанк-АСТ, РТС-тендер, OTC, Берёзка, Tender.pro (поиск только через защищённый от ботов JavaScript),
ЭТП ГПБ и Портал поставщиков Москвы (не отвечают), SberB2B, Bidzaar, Comita, РАД 223-ФЗ (реестр только после входа).
ГИС Торги и РАД / Lot-online убраны сознательно: там только продажа и аренда имущества.

## Уведомления

- **Браузер** — включите в настройках, разрешите уведомления сайту. Работают, пока вкладка открыта.
- **Telegram** — задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, включите переключатель в настройках.

```

src/legal-check.js           — ссылка «Юридическая проверка» на карточку заказчика

src/sources/combined.js   — параллельный опрос ЕИС и площадок

src/rss.js, src/tenders.js, src/inn.js, src/notify.js — парсер RSS, нормализация, ИНН, Telegram
public/                   — интерфейс (vanilla JS, без сборки)
test/                     — node:test (парсер, запросы, хранилище, планировщик)

```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка здоровья сервиса для систем мониторинга / облаков (без входа) |
| POST | `/api/login` | `{login, password}` → cookie-сессия на 14 дней |
| POST | `/api/logout` | закрыть сессию |
| GET | `/api/me` | текущий пользователь |
| POST | `/api/me/password` | `{current, next}` — смена своего пароля |
| POST | `/api/setup` | создать первого администратора, только пока пользователей нет |
| GET / POST / PATCH / DELETE | `/api/users[/:id]` | учётные записи, только администратор. Роль `admin` или `employee` |
| GET | `/api/state` | настройки, watchlist, статус планировщика, счётчики, текущий пользователь |
| GET | `/api/analytics` | сводная аналитика: суммы НМЦК, распределение по законам, этапам, топ заказчиков и поставщиков |
| GET | `/api/tenders?q=&nomen=&kind=&law=&source=&minPrice=&maxPrice=&onlyNew=1&onlyOpen=1&favorite=1&archived=1\|any&sort=&actual=1&region=&subject=supply\|works&ctype=heat\|municipal\|industrial\|budget\|other&method=auction\|quotes\|proposals\|contest\|other&smp=only\|exclude&published=дней&minDays=дней` | лента. `archived=any` — вместе с архивом, `sort=favorited` — по дате добавления в избранное. `source` — `zakupki` или id площадки (`roseltorg`, `tektorg`…). Цена — «от» и «до», можно с пробелами: `1 000 000` |
| GET | `/api/tenders.csv?…` | та же выборка в CSV |
| GET | `/api/customers/procurement?inn=&name=` | объём закупок заказчика: RSS контрактов ЕИС по ИНН и карточки из ленты. График по годам. В демо ЕИС не опрашивается |
| PATCH | `/api/tenders/:id` | `{seen, favorite, archived, comment}`; `comment` — заметка до 2000 символов, пустая строка удаляет. Сотрудник не меняет `archived` |
| GET | `/api/crm` | воронка: этапы, сотрудники, карточки сделок |
| POST | `/api/crm` | `{tenderId}` — взять закупку в воронку (и в избранное) |
| PATCH | `/api/crm/:id` | этап, ответственный, сумма предложения, следующий шаг, причина отказа |
| POST | `/api/crm/:id/notes` | `{text}` — комментарий в историю |
| DELETE | `/api/crm/:id` | убрать из воронки, только администратор |
| POST | `/api/tenders/:id/documents` | начать извлечение документации в PDF (202, ход — SSE-событие `documents`) |
| GET | `/api/tenders/:id/documents` | состав: файлы, страницы, примечания, оригиналы |
| GET | `/api/tenders/:id/documents.pdf` | собранный PDF (открывается в браузере) |
