# 🕵️ Tender Spy — мониторинг тендеров по ИНН и номенклатуре

Веб-приложение, которое следит за закупками в ЕИС (zakupki.gov.ru, 44-ФЗ / 223-ФЗ / 615-ПП)
по списку наблюдения:

- **предприятия по ИНН** — извещения, где предприятие выступает заказчиком, и контракты,
  где оно поставщик (что и у кого оно выигрывает);
- **номенклатура** — ключевые слова (с учётом словоформ) и/или коды ОКПД2.

Новые закупки подсвечиваются в ленте, приходят уведомлением в браузер и, при желании, в Telegram.

## Запуск

```bash
cd tender-spy
npm install
npm start            # http://localhost:3000 — реальные данные ЕИС
npm run demo         # демо-режим: карточки генерируются локально, без сети
```

С переменными из файла: `cp .env.example .env`, затем `npm run start:env`.

Требуется Node.js ≥ 18 (для `start:env` — ≥ 20.6).

### Развертывание в облаке Amvera (amvera.ru)

В корне репозитория подготовлены конфигурационные файлы `amvera.yml` и `Dockerfile`:
- Среда: Node.js 20.
- Порт: 3000 (по умолчанию).
- Постоянное хранилище: `/data` (база автоматически монтируется по пути `/data/db.json` при наличии переменной `AMVERA` или `TENDER_SPY_DATA=/data/db.json`).
- Для развертывания:
  1. Создайте приложение в Amvera.
  2. Добавьте remote: `git remote add amvera https://git.amvera.ru/<username>/<app-name>`.
  3. Отправьте ветку: `git push amvera <ваша-ветка>:master`.
  4. В панели Amvera задайте необходимые переменные (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TENDER_SPY_POLL_MIN`).

## Как пользоваться

1. **Наблюдение** → добавьте ИНН предприятий (проверяется контрольная сумма) и позиции номенклатуры.
   Для предприятия выберите роль: заказчик (искать его извещения), поставщик (искать его контракты) или обе.
2. Нажмите **Опросить сейчас** или дождитесь автоопроса (интервал — в настройках).
3. **Лента** → фильтры по предприятию, номенклатуре, закону, типу (извещение/контракт), цене, сроку подачи.
   На каждой карточке видно, *почему* она попала в выборку (чипы «ИНН…» / «ключевая фраза» / «ОКПД2»).
   Полупрозрачный чип — совпадение выдано ЕИС, но в тексте карточки не подтверждено.
4. Действия по карточке: ★ избранное, ✓ прочитано, 🗄️ архив. Смена этапа закупки снова делает карточку «новой».
5. **CSV** — выгрузка текущей выборки (разделитель `;`, кодировка UTF-8 с BOM — открывается в Excel).
6. **Журнал опросов** — какие запросы ушли, сколько найдено, ошибки ЕИС.

## Откуда данные

ЕИС не предоставляет публичного REST API; приложение читает **RSS расширенного поиска**:

| Что ищем | Запрос к ЕИС |
|---|---|
| Извещения по ИНН заказчика | `/epz/order/extendedsearch/rss.html?searchString=<ИНН>&af=on&fz44=on&fz223=on…` |
| Извещения по номенклатуре | то же с `searchString=<слова>` и/или `okpd2IdsCodes=<код>` |
| Контракты по ИНН поставщика | `/epz/contract/search/rss.html?supplierInn=<ИНН>…` |

Точные URL можно увидеть в разделе «Наблюдение → Какие запросы уйдут в ЕИС». Имена параметров
вынесены в `src/sources/zakupki.js` (`QUERY_TEMPLATES`) — если ЕИС переименует поля формы, правится одно место.

Важные ограничения самого ЕИС:

- **участники открытой закупки не публикуются до итогового протокола** — поэтому «участие» предприятия
  видно либо как заказчика (извещение), либо как победителя (контракт);
- ЕИС ограничивает частоту запросов и доступ с зарубежных IP — используйте паузу `TENDER_SPY_REQUEST_DELAY_MS`
  ≥ 1000 мс и запускайте сервер из России (или через российский прокси);
- в RSS попадают первые 50 записей на запрос по дате обновления — для широких ключевых слов уточняйте фразу или ОКПД2.

## Уведомления

- **Браузер** — включите в настройках, разрешите уведомления сайту. Работают, пока вкладка открыта.
- **Telegram** — задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, включите переключатель в настройках.

## Структура

```
server.js                 — HTTP API (Express) + статика + SSE
src/config.js             — настройки из окружения / argv
src/store.js              — JSON-хранилище (watchlist, тендеры, журнал, настройки)
src/scheduler.js          — периодический опрос, слияние, подсчёт новых, уведомления
src/sources/zakupki.js    — запросы к ЕИС и разбор RSS в единую модель карточки
src/sources/demo.js       — офлайн-генератор карточек для демо
src/rss.js, src/tenders.js, src/inn.js, src/notify.js — парсер RSS, нормализация, ИНН, Telegram
public/                   — интерфейс (vanilla JS, без сборки)
test/                     — node:test (парсер, запросы, хранилище, планировщик)
data/db.json              — база (создаётся автоматически, в git не попадает)
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка здоровья сервиса для систем мониторинга / облаков |
| GET | `/api/state` | настройки, watchlist, статус планировщика, счётчики, краткая аналитика |
| GET | `/api/analytics` | сводная аналитика: суммы НМЦК, распределение по законам, этапам, топ заказчиков и поставщиков |
| GET | `/api/tenders?q=&company=&nomen=&kind=&law=&onlyNew=1&onlyOpen=1&favorite=1&archived=1&sort=` | лента |
| GET | `/api/tenders.csv?…` | та же выборка в CSV |
| PATCH | `/api/tenders/:id` | `{seen, favorite, archived, comment}` |
| POST | `/api/tenders/mark-all-seen` | всё прочитано |
| POST / PATCH / DELETE | `/api/companies[/:id]` | предприятия `{inn, name, role, note}` |
| POST | `/api/companies/batch` | пакетное добавление ИНН списком `items: [...]` |
| POST / DELETE | `/api/nomenclature[/:id]` | номенклатура `{keyword, okpd2}` |
| GET | `/api/watchlist/export` | экспорт списка наблюдения в JSON |
| POST | `/api/watchlist/import` | импорт списка наблюдения `{ companies, nomenclature, replace }` |
| PATCH | `/api/settings` | интервал, законы, фильтр этапа, Telegram |
| POST | `/api/telegram/test` | тестовая отправка сообщения в Telegram для проверки подключения |
| POST | `/api/scan` | запустить опрос сейчас |
| GET | `/api/runs` | журнал опросов |
| GET | `/api/queries` | какие URL уйдут в ЕИС |
| GET | `/api/events` | SSE: `run:start`, `run:done` |
